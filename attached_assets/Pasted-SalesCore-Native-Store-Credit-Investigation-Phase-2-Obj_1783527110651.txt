SalesCore Native Store Credit Investigation (Phase 2)
Objective

This is an investigation-only task.

Do not modify production code.

Do not implement any workaround.

Do not add new fallback logic.

The purpose of this investigation is to determine whether SalesCore can create orders that are identical to native BigCommerce storefront orders when Store Credit is redeemed.

The previous investigation eliminated several approaches. This phase should only focus on the remaining native possibilities.

Architecture Goal

The SalesCore POS should not implement its own Store Credit engine.

Instead, it should become another client of BigCommerce's native checkout flow.

The end result should be that a POS-created order is functionally and structurally identical to a storefront-created order.

BigCommerce should remain the financial source of truth.

Important Architecture Clarification

Do not assume our CRM is the master Store Credit ledger.

Instead, determine whether BigCommerce should be treated as the authoritative Store Credit balance.

Preferred architecture:

BigCommerce Store Credit

↓

POS reads current balance

↓

Native BigCommerce Checkout

↓

BigCommerce updates remaining balance

↓

SalesCore mirrors the updated balance back into CRM

If technical limitations require a different architecture, document why.

Success Criteria

This investigation is complete only when one of the following has been proven with evidence:

Option A

SalesCore can fully reproduce native BigCommerce Store Credit.

or

Option B

BigCommerce's public APIs make native Store Credit impossible to reproduce, with documented evidence explaining why.

No code should be written until one of these conclusions has been reached.
