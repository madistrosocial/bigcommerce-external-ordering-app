# POS WHOLESALE MODE & DRAFT WORKFLOW IMPROVEMENTS

## Objective

Improve the Sales POS experience for very large wholesale orders (100–500+ line items) by introducing a dedicated Wholesale Mode and improving the Draft workflow.

This update is primarily a frontend/UI improvement. The existing POS workflow, business logic, pricing, discounts, checkout, inventory validation, barcode scanning, customer search, and BigCommerce integration should remain unchanged unless explicitly stated below.

This should be implemented as a non-breaking enhancement.

---

# Part 1 — Add Fullscreen Button

Add a new toolbar button near the top of the POS.

Example:

□ Fullscreen

Behavior:

* Uses the browser Fullscreen API.
* Expands the application to occupy the entire monitor.
* Hides browser UI (address bar, tabs, etc.) where supported.
* Clicking again exits fullscreen.
* Remember the user's last preference locally.

No other functionality changes.

---

# Part 2 — Add Wholesale Mode

Add a toggle beside the Fullscreen button. Dont add a name to the button, just a button for the wholesale mode.

Example:

□ Wholesale Mode

Behavior:

This is a dedicated layout optimized for reviewing and editing very large wholesale orders.

Current POS remains the default.

Wholesale Mode is optional.

Persist the user's preference locally.

---

# Part 3 — Wholesale Layout

When Wholesale Mode is enabled:

Hide:

* Favorites
* Sale tab

These consume vertical space but provide little value while reviewing large wholesale orders.

Keep visible:

* Customer Search
* Product Search
* Product Search Results

These continue to function exactly as they do today.

No product functionality changes.

---

# Part 4 — Full Width Cart

This is the biggest visual change.

Current layout:

Products | Cart Sidebar

Wholesale Mode:

Customer Search

Product Search

Product Search Results

---

FULL WIDTH CART

---

The cart should no longer be a narrow right sidebar.

It should occupy the entire content width below the search section, similar to a traditional wholesale cart/invoice editor.

This layout is inspired by the BigCommerce storefront cart, but must retain all Sales POS functionality.

---

# Part 5 — Cart Line Layout

Replace expandable item cards with always-visible editing controls.

Every line item should display all editable controls without requiring expansion.

Each row should contain:

* Product Image
* Product Name
* SKU
* Variant
* Available Stock
* Quantity controls (- Qty +)
* Unit Price
* Discount %
* Price Override
* Line Total
* Remove Item

Display these on a single horizontal row whenever practical.

The goal is maximum information density while maintaining readability.

No expand/collapse interaction should be required in Wholesale Mode.

---

# Part 6 — Row Editing

Every row should always expose:

Quantity

Price Override

Discount

Delete

No extra clicks.

No expanding.

Editing multiple items should feel similar to editing a spreadsheet.

---

# Part 8 — Sticky Footer

Only ONE sticky footer should exist.

Always pinned to the bottom of the viewport.

Contents:

Total
Item count

Save Draft

Checkout

Nothing else.

Those remain inside the normal Order Summary at the bottom of the page.

The sticky footer exists only to eliminate excessive scrolling when processing large carts.

---

# Part 9 — Save Draft Behavior

When user save cart as Draft, dont clear the cart. Keep everything as is so user can continue with the current cart without interuption. Only notify that the cart has been saved as draft.

---

# Part 11 — Preserve Existing Functionality

Do NOT modify:

Barcode scanning

Product search

Inventory lookup

Customer lookup

Checkout process

Pricing

Discount calculations

Notes

Draft storage format

BigCommerce integration

This update should only improve usability.

---

# Expected Result

The POS should now support two optimized workflows.

Normal Mode

Current POS.

Best for everyday orders.

Wholesale Mode

Optimized for reviewing and editing very large wholesale orders.

The cashier should be able to:

* review hundreds of line items
* modify quantities quickly
* edit prices
* apply discounts
* review stock
* save drafts
* continue checkout

without repeatedly expanding item cards or losing the Checkout button during long scrolling sessions.

The Save Draft workflow should also become significantly safer by preserving the current cart after saving, while the Draft Reload issue should be fully investigated to ensure restored carts behave identically to freshly created carts.
