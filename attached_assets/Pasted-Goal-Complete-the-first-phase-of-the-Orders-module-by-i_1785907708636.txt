Goal

Complete the first phase of the Orders module by improving usability and consistency. Do not redesign the page or change the existing layout. The current UI direction is correct and should remain consistent with the CRM module.

1. Default Sales Channel

Change the default Sales Channel filter from:

Sales App

to:

All Orders

The Orders page should always load showing all orders unless the user explicitly changes the filter.

2. Add Sales Channel Column

Add a new column to the Orders list.

Column:

Sales Channel

Display one of:

Sales App
Website
BigCommerce

(or whatever values currently exist in the backend)

Use compact badges or small text consistent with the current design language.

This column should appear by default whenever viewing All Orders.

Suggested column order:

Order #
Customer
Sales Channel
Status
Date
Total
Actions

Keep column sizing compact.

3. Customer Links

Verify customer links work consistently everywhere.

Customer/company names should navigate to the CRM customer page from:

Orders list
Expanded order preview
Sales App Order Detail
BigCommerce Order Detail

Use the existing CRM customer lookup.

4. Product Links (Preparation)

Do not create Product CRM yet.

Instead:

Wrap every product name in a reusable ProductLink component.
For now it can behave as plain text or a disabled link.
The component should be reusable later when Product CRM is implemented.

Do not hardcode future URLs.

5. Expanded Order Preview

Keep the current layout.

Improve only the information shown.

Each expanded preview should display:

Customer
Billing Address
Products
Order Summary

Order Summary should include:

Subtotal
Discount (only when > 0)
Tax (only when > 0)
Shipping (only when > 0)
Grand Total

Hide rows whose values are zero.

6. Full Order Detail

Keep the current layout.

Do not redesign it.

Only improve organization and usability.

Customer section

Continue linking customer names to the CRM Customer page.

Products table

Continue showing:

Product
Quantity
Unit Price
Discount
Tax
Line Total

Rules:

Display "-" instead of "$0.00" whenever line tax equals zero.
Only display tax values when tax actually exists.
Continue fetching line-item tax directly from the BigCommerce API.
Do not store line-item tax in the local database.
Move Notes Below Products

Reorganize the page so the Notes section is moved below the Products / Line Items section.

The order flow should become:

Customer Information
Products / Line Items
Order Summary
Notes

The Notes section should clearly separate:

Customer Notes

Display notes entered by the customer during checkout.

Read-only.

Staff Notes

Display internal staff notes.

If the logged-in user has the existing CRM Notes permission/scope already implemented in the application:

Show an Edit button.
Reuse the existing CRM Notes editor/modal/component.
Do not create a new notes editor.
Reuse the existing permission validation already used by the CRM module.

If the user does not have permission:

Display the notes as read-only.
Hide the Edit action.

The goal is to reuse the existing CRM Notes permission system rather than creating another permission specifically for Orders.

7. Order Summary

Only display rows when values exist.

Possible rows:

Subtotal
Discount
Tax
Shipping
Grand Total

Hide Discount, Tax and Shipping rows when zero.

8. Action Menu

Keep the existing context menu.

Current actions:

Print Invoice
Send Invoice
Download Invoice

Leave:

Re-order

visible but disabled/inactive.

Do not implement Re-order yet.

No additional actions at this stage.

9. Desktop & Mobile

Maintain the current responsive implementation.

Desktop and tablet should remain information-dense.

Mobile should continue using the compact expandable card layout.

Do not redesign the mobile experience.

10. Architecture Rules
Reuse existing CRM components whenever possible.
Reuse existing badges, buttons, cards, dialogs and table styling.
Continue following the application's standardized UI language (Inter typography, reduced shadows, standardized spacing, reusable shadcn components).
Avoid duplicate components if an existing reusable component already exists.
Continue using the local database as the primary source where available, with BigCommerce API only for data not currently mirrored (such as per-line tax).
Out of Scope

Do not implement:

Product CRM
Re-order functionality
Additional order actions
Purchasing workflow
Inventory workflow
Quote conversion
Database redesign

This phase is focused on polishing and completing the Orders module while keeping it consistent with the CRM module and the overall ERP architecture.
