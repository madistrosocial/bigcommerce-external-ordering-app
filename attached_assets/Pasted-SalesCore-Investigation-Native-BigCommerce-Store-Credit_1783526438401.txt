SalesCore Investigation
Native BigCommerce Store Credit Implementation
Objective

This is an investigation and architecture planning task.

Do not implement production code yet.

Our objective is to make the SalesCore POS create orders that are identical to orders created through the native BigCommerce storefront when Store Credit is used.

BigCommerce is the source of truth.

The POS should behave as another checkout client of BigCommerce, not implement its own Store Credit logic.

Current Issue

The POS currently does not create Store Credit orders the same way as native BigCommerce.

Instead, Store Credit is being transformed into alternative mechanisms such as:

Discounts
Gift Certificates
Manual balance manipulation

These are workarounds.

We do not want workarounds.

We want the same native Store Credit implementation used by BigCommerce itself.

4. Native Store Credit Goal

The objective is for POS-created orders to match native BigCommerce.

Specifically:

Product prices remain unchanged.
Store Credit appears as Store Credit, not Discount.
Store Credit appears in the order history exactly as it does for storefront orders.
Store Credit is processed through the same native mechanism used by BigCommerce.
The resulting BigCommerce order should be indistinguishable from a storefront order.

Success Criteria

The investigation is successful if we can determine how to make SalesCore produce the exact same BigCommerce order structure as the native storefront when Store Credit is redeemed.

The goal is not to make Store Credit "work."

The goal is to make SalesCore indistinguishable from the native BigCommerce checkout for Store Credit handling. Only after confirming that architecture should implementation begin.
