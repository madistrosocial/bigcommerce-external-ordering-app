2. INVENTORY AUDIT QUEUE
==================================================

Create a new module:

Inventory > Inventory Audit

This module exists specifically to correct SKUVault inventory after manual inventory pushes.

Business reason:

A manual inventory push may temporarily increase inventory in BigCommerce/SKUVault so an order can proceed. However, the physical warehouse inventory must subsequently be audited in SKUVault so SKUVault's inventory and sales history remain accurate.

Every manual inventory push to SKUVault should therefore create an audit task.

IMPORTANT:
If the same SKU is manually pushed multiple times before it is audited, DO NOT create multiple audit tasks.

There must only be ONE pending audit task per SKU.

Example:

SKU ABC-123
Manual push +2
Manual push +3
Manual push +1

Result:

ONE audit task for ABC-123.

The task should contain enough history to show the warehouse user that the SKU had multiple manual pushes, including the relevant push history/total pushed quantity.

7. Record timestamp.
8. Record previous system quantity.
9. Record physical quantity.
10. Record variance.
11. Record reason.

==================================================
9. PROTECT AGAINST INVENTORY OVERWRITE
==================================================

This is critical.

Do NOT perform historical backfill by blindly overwriting current SKUVault inventory.

The audit task exists because the warehouse will physically verify the current inventory.

The system must NEVER assume:

"manual push quantity = current physical inventory."

Instead:

Manual push creates an audit task.

Warehouse user physically counts the SKU.

Warehouse user enters the current physical count.

That physical count becomes the authoritative adjustment sent to SKUVault.

This protects against situations where:

- new inventory was received after the manual push
- another order was fulfilled
- another inventory audit already corrected the SKU
- inventory changed for another legitimate reason

The system should always show the current SKUVault quantity when the audit is opened.

If practical, refresh the SKUVault quantity immediately before completing the audit.

If the SKUVault quantity changed since the task was created, display a warning such as:

"SKUVault inventory changed since this audit task was created. Current system quantity: X. Please verify the physical count before submitting."

Do not overwrite the physical count automatically.

10. AUDIT TASK DEDUPLICATION
==================================================

Enforce this at the DATABASE level.

A SKU must not have multiple pending audit tasks.

If the same SKU is manually pushed multiple times:

- Reuse the existing pending audit task.
- Update its push history/aggregate information.
- Do not create another pending task.

Once an audit is completed, a future manual push may create a new audit task.

Use a database constraint/index or another reliable transactional mechanism so concurrent requests cannot create duplicate pending tasks.

Do NOT rely only on frontend checks.
