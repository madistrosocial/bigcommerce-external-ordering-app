Reports Module Architecture

The Reports module should be built around a shared Report Engine. The Report Engine should contain all reusable reporting functionality, while individual reports are implemented as separate sub-modules that utilize the engine.

The goal is to avoid duplicating filters, export logic, audit logging, SQL builders, permissions, pagination, and UI components across multiple reports.

The first report to be implemented is Sales Report.

Report Engine Responsibilities

The Report Engine should provide reusable functionality including:

Filtering
Date Range
Brand
Category
Product Search
Multi Select
Custom filters supplied by each report
Query Builder

Each report supplies:

Data source
SQL query
Default sorting
Available filters
Available columns

The Report Engine handles executing and rendering the results.

Table Renderer

Reusable table component supporting:

Pagination
Sorting
Sticky headers
Loading states
Empty states
Export Service

Shared export functionality:

Excel
CSV

Exports should automatically respect:

Current filters
Current sorting
Current report
Current view
Audit Logging

Shared audit logging for all reports.

Every export should log:

User
Timestamp
Report
View
Filters
Export type

No report should implement its own logging.

Permissions

Allow future report-level permissions such as:

View Report
Export Report

without modifying each report individually.

Each future report should only define:

Its SQL/business logic
Its columns

Everything else (rendering, filtering, exporting, pagination, permissions, audit logging, etc.) should come from the shared Report Engine.
