SalesCore Native Store Credit Investigation (Final Validation)
Objective

This is the final investigation before implementation.

Do not implement production code.

Do not create workarounds.

The objective is to conclusively determine whether the SalesCore POS can generate orders that are financially and functionally equivalent to native BigCommerce storefront orders when Store Credit is redeemed.

If the answer is yes, we will implement that architecture.

If the answer is no, we need documented evidence explaining exactly why.

Background

Previous investigations have already confirmed:

✅ BigCommerce v3 Customer API can update Store Credit (store_credit_amounts).
✅ BigCommerce is capable of maintaining Store Credit balances natively.
✅ Management Checkout cannot apply Store Credit because checkout.customer_id is not populated.
✅ Orders API cannot directly create native Store Credit orders.
❌ Gift Certificates, discounts, temporary balance manipulation, or other workaround implementations are not acceptable.

The only remaining question is whether the native Storefront checkout flow can be reused programmatically.

Important Principles

Do not think about Xero.

Do not think about Parex Bridge.

Do not think about accounting workarounds.

The only goal is:

Can the POS create the same BigCommerce order that the native storefront creates?

If BigCommerce receives the same order structure, every downstream integration should naturally behave the same.

Investigation Tasks
Task 1 — Customer Impersonation Token

Determine why the Customer Impersonation Token endpoint returns 404.

Specifically investigate:

Is this endpoint available on our BigCommerce plan?
Does it require an OAuth App instead of an API Account?
Does it require additional OAuth scopes?
Does it require different authentication?
Does it require channel configuration?
Is it unavailable because of plan restrictions?
Is there another officially supported authentication mechanism for server-side storefront checkout?

Do not guess.

Verify using:

Official BigCommerce documentation
Live API testing
Current store configuration
Task 2 — Storefront Checkout APIs

If Customer Impersonation becomes available:

Verify whether SalesCore can perform the complete native storefront checkout flow.

Determine whether the following sequence is officially supported:

Authenticate customer.
Create storefront cart.
Apply native Store Credit.
Complete checkout.
Generate native BigCommerce order.

Determine whether Store Credit is applied exactly as the storefront does.

Task 3 — Compare Final Orders

If Task 2 succeeds:

Create:

One native storefront order.
One programmatically created storefront order.

Compare:

Order JSON
Transactions
Payment records
Store Credit
Discounts
Payment Method
Timeline
Order Events
Financial summary

The goal is not byte-for-byte equality.

The goal is financial and functional equivalence.

Specifically verify that:

Store Credit appears as Store Credit.
Product prices remain unchanged.
No fake discounts exist.
No modified line-item pricing exists.
Native payment records are created.
Task 4 — If Storefront Checkout Cannot Be Used

If native storefront checkout cannot be accessed programmatically, determine exactly why.

Document:

API limitation
Authentication limitation
Plan limitation
Product limitation
Missing endpoint
Unsupported workflow

Provide evidence for every conclusion.

Do not speculate.

Task 5 — Final Recommendation

Return one of only three conclusions.

Option A

Native Store Credit implementation is fully achievable.

Provide the recommended architecture.

Option B

Native implementation is achievable with specific requirements.

Example:

OAuth App
Additional scopes
Plan upgrade
Store configuration

Clearly document every prerequisite.

Option C

Native implementation is not possible using currently supported public BigCommerce APIs.

Provide documented evidence.

Explain exactly which API limitation prevents it.

Do not recommend a workaround.

Constraints

Do not:

Modify production code.
Implement Store Credit.
Implement Discounts.
Implement Gift Certificates.
Implement temporary balance synchronization.
Implement fallback logic.

This is an investigation only.

Deliverables

Provide a technical report containing:

Why Customer Impersonation Token currently returns 404.
Whether OAuth would enable it.
Whether our BigCommerce plan supports it.
Whether native Storefront checkout can be used programmatically.
Whether SalesCore can create financially and functionally equivalent native BigCommerce orders.
If not, provide the exact technical limitation preventing it.
The recommended implementation architecture if native support is confirmed.
Success Criteria

The investigation is complete only when one of these statements can be proven with evidence:

A. SalesCore can use the native BigCommerce Storefront checkout flow to create Store Credit orders that are financially and functionally equivalent to storefront orders.

OR

B. BigCommerce's currently supported public APIs make this impossible, with documented evidence identifying the exact limitation.

No production code should be written until one of these two conclusions has been reached.
