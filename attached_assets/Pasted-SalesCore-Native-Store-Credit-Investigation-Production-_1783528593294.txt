SalesCore Native Store Credit Investigation
Production Validation (Final Confirmation)
Objective

The application is now connected to our live production BigCommerce store.

The previous investigation was performed against an App Developer Sandbox, so several findings (Customer Impersonation Token, Storefront APIs, channel status, plan restrictions, etc.) may not accurately reflect production behavior.

This investigation is intended to validate those remaining unknowns against production.

Do not implement any production code.

Do not modify any business logic.

This is a read-only investigation unless explicitly instructed otherwise.

⚠️ Production Safety

This is our live production store containing real customers, orders, and financial data.

Treat production as read-only whenever possible.

Do not:

Modify customer Store Credit balances.
Create production orders.
Update customer information.
Delete or modify products.
Change inventory.
Change pricing.
Change customer accounts.
Change store configuration.
Change channels.

If a write operation is absolutely required to validate an API capability:

Use only a dedicated internal test customer approved for testing.
Use the smallest possible test values (e.g., $0.01 or $1.00).
Immediately restore the original value after testing.
Confirm cleanup before proceeding.
Document every write performed.

No production customer should ever be impacted.

Investigation Scope

The previous investigation already confirmed:

v3 Customer Store Credit update capability
Management Checkout limitations
Orders API limitations

These do not need to be repeated unless production behaves differently.

Focus only on the remaining unknowns.

Task 1 — Customer Impersonation Token

Verify whether the Customer Impersonation Token endpoint is available in production.

Determine:

Does it exist?
Does it require OAuth?
Does it require different authentication?
Does it require additional scopes?
Does it require an active storefront channel?
Does it require a production plan?

If unavailable:

Document the exact reason with evidence.

Task 2 — Customer Login Flow

Investigate the officially supported Customer Login flow.

Determine whether SalesCore can authenticate a customer into the native storefront checkout.

Document:

Required OAuth configuration
Required scopes
Required credentials
Required JWT generation
Supported authentication flow

No implementation.

Task 3 — Native Storefront Checkout

Determine whether a server-side process can execute the native storefront checkout while maintaining customer context.

Specifically determine whether:

checkout.customer_id becomes populated.
Store Credit can be applied natively.
The resulting order contains native Store Credit.
Native payment records are created.

Do not place production orders unless absolutely necessary.

If an end-to-end checkout test is required:

Use a dedicated internal test customer.
Use a dedicated test product with negligible value.
Cancel or clean up the test order afterward if appropriate.
Task 4 — Production vs Sandbox Comparison

Compare production behavior against the previous sandbox investigation.

Specifically verify whether the following differences were caused by the sandbox:

Customer Impersonation Token
Storefront authentication
Storefront checkout
Channel restrictions
Headless APIs

Document every difference.

Task 5 — Final Architecture Validation

Based on production results, answer:

Can SalesCore create orders that are financially and functionally equivalent to native BigCommerce storefront orders when Store Credit is redeemed?

If yes:

Describe the architecture.

If no:

Identify the exact BigCommerce limitation preventing it.

Do not recommend workarounds.

Deliverables

Return a technical report containing:

Production findings.
Differences from sandbox.
Remaining blockers.
Whether native Store Credit implementation is fully achievable.
Recommended architecture.
Any required OAuth configuration.
Any required BigCommerce plan or feature prerequisites.
Constraints

Do not:

Write production code.
Implement Store Credit.
Implement Discounts.
Implement Gift Certificates.
Implement temporary balance synchronization.
Implement fallback logic.
Modify existing checkout code.

Investigation only.

Success Criteria

This investigation is complete only when one of the following is proven with evidence:

Option A

SalesCore can use supported BigCommerce production APIs to create orders that are financially and functionally equivalent to native storefront orders using Store Credit.

Option B

The production BigCommerce APIs still prevent native Store Credit implementation, with documented evidence identifying the exact limitation.

Only after this production validation should implementation begin.
