# User Default Landing Page Configuration

## Objective

Allow administrators to define the default page users are redirected to after login.

This solves two issues:

1. Different teams need different starting pages.
2. Users without Dashboard access are still landing on Dashboard because it is currently the global default route.

This is not a full security overhaul.

This is a navigation and user experience enhancement.

---

# Current Problem

Current behavior:

```text
User Login
↓
Dashboard
```

even when:

```text
dashboard:view = false
```

The Dashboard menu item may be hidden but the user still lands on the Dashboard page immediately after login.

This creates confusion and partially bypasses intended navigation restrictions.

---

# New Behavior

After login:

```text
User Login
↓
User Default Landing Page
```

Example:

```text
Sales Rep
↓
CRM Customers
```

```text
Inventory User
↓
Inventory Push
```

```text
Admin
↓
Dashboard
```

---

# Database

Add new field to users table:

```sql
default_landing_page VARCHAR(100)
```

Default:

```text
/dashboard
```

# Login Flow

Current:

```text
Login
↓
Dashboard
```

Replace with:

```text
Login
↓
Read User Default Landing Page
↓
Redirect
```

---

# Permission Validation

Before redirecting:

Verify user has permission to access the configured page.

Example:

```text
Default Landing Page = Dashboard
```

but:

```text
dashboard:view = false
```

Then:

Do NOT redirect to Dashboard.

---

# Fallback Logic

If configured page is unavailable:

Redirect to first accessible page.

Priority order:

```text
CRM Customers
Orders
Products
Inventory Push
Dashboard
```

Example:

```text
Dashboard Disabled
CRM Customers Enabled
```

Redirect:

```text
CRM Customers
```

---

# User Groups

No group-level landing pages required yet.

This should be configured per user.

Reason:

Some support reps may want CRM Customers.

Some managers may want Dashboard.

Keep flexibility.

---

# Future Compatibility

Design so group-level defaults can be added later.

Potential future structure:

```text
Role Default Landing Page
```

with optional user override.

Do not implement now.

---

# UI Requirements

User management page should display:

```text
Default Landing Page
```

alongside existing user settings.

# Testing Requirements

Verify:

### Dashboard User

```text
Dashboard access enabled
Default = Dashboard
```

Result:

```text
Redirect to Dashboard
```

---

### Sales Rep

```text
Dashboard access disabled
Default = CRM Customers
```

Result:

```text
Redirect to CRM Customers
```

---

### Invalid Landing Page

```text
Dashboard permission removed
```

Result:

```text
Redirect to first accessible module
```

```text
Default = Dashboard
```

No breaking changes.
