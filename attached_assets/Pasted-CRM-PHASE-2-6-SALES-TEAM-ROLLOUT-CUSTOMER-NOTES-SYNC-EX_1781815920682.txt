CRM PHASE 2.6 – SALES TEAM ROLLOUT, CUSTOMER NOTES SYNC & EXPORT SECURITY

OBJECTIVE

Prepare the CRM for daily use by sales representatives before Zoho CRM integration.

This phase focuses on:

1. RBAC-based CRM customer visibility
2. Assigned Rep filtering and assignment permissions
3. BigCommerce Customer General Notes synchronization
4. CRM customer list usability improvements
5. CRM export security and RBAC

The goal is for sales reps to log in and immediately see only the accounts assigned to them, along with customer health status, notes, and customer intelligence information.

==================================================================
FEATURE 1: CRM VISIBILITY RBAC
==============================

Create a new CRM-specific RBAC permission.

Permission Name:

CRM_VISIBILITY_SCOPE

Available Values:

* ALL_CUSTOMERS
* ASSIGNED_AND_UNASSIGNED
* ASSIGNED_ONLY

Behavior:

ALL_CUSTOMERS

* User can view all CRM customers.
* No restrictions.

ASSIGNED_AND_UNASSIGNED

* User can view:

  * Customers assigned to themselves
  * Customers without an assigned rep

ASSIGNED_ONLY

* User can only view customers assigned to themselves.

Implementation:

Add visibility_scope field to CRM permissions.

Example:

Admin
→ ALL_CUSTOMERS

Sales Manager
→ ALL_CUSTOMERS

Sales Rep
→ ASSIGNED_ONLY

When loading CRM Customers page, automatically apply visibility filtering server-side.

Do not rely on frontend filtering.

The backend query must enforce visibility scope.

FEATURE 4: CRM ASSIGN REP PERMISSION
====================================

Current behavior:

Only Admin can assign sales reps.

Replace with RBAC permission.

New Permission:

CRM_ASSIGN_REP

Users with permission:

Can assign customer accounts.

Users without permission:

Cannot assign or reassign accounts.

UI Behavior:

Hide Assign Rep button if permission is missing.

Do not rely solely on frontend.

Backend must validate permission before saving.

Examples:

Admin
→ Allowed

Sales Manager
→ Allowed

Sales Rep
→ Not Allowed

Operations Manager
→ Allowed if permission granted

Assignment capability must be completely independent from Admin role.

FEATURE 5: BIGCOMMERCE CUSTOMER GENERAL NOTES SYNC
==================================================

PURPOSE

BigCommerce Customer Notes currently contain valuable customer information such as:

* Account creation notes
* Tax documents
* Verification notes
* Customer preferences
* General account concerns

CRM should display and edit this information.

==================================================================
BIGCOMMERCE CUSTOMER NOTE AS MASTER REPOSITORY
==============================================

Customer-level notes without an order association should sync into BigCommerce Customer Notes.

Examples:

* General
* Sales
* Follow Up
* Issue
* Internal

Order-linked notes should NOT sync.

Order notes remain inside order history.

==================================================================
CUSTOMER PROFILE CHANGES
========================

Add a new section:

GENERAL NOTES

Display:

BigCommerce Customer Notes

Editable from CRM.

When saved:

Update BigCommerce Customer Notes.

==================================================================
NOTE STRUCTURE
==============

Reserve structure inside BigCommerce Customer Notes.

Format:

=== CUSTOMER GENERAL NOTES ===

[Permanent account information]

=== CRM HISTORY ===

[Generated CRM entries]

Each CRM-generated entry should contain:

* Date
* User
* Type
* Source
* Content

Example:

---

Date: 2026-06-15 10:42 AM
Type: Follow Up
User: Rose
Source: CRM

Called customer regarding inactive account.

---

Notes must remain human readable.

CRM should append entries rather than overwrite history.

==================================================================
CRM NOTE BEHAVIOR
=================

Customer-Level Notes

Sync To:

BigCommerce Customer Notes

Order-Level Notes

Do NOT sync

Remain attached to order records.

FEATURE 6: CRM EXPORT RBAC
==========================

PURPOSE

CRM customer data contains:

* Revenue
* Order Counts
* Store Credit
* Customer Health
* Customer Contact Information
* Assigned Sales Reps

Exporting this data must be controlled through RBAC.

==================================================================
NEW PERMISSION
==============

Create:

CRM_EXPORT

This single permission controls all CRM export functionality.

==================================================================
UI BEHAVIOR
===========

Current buttons:

* Export CSV
* Export Excel

Users WITH permission:

Buttons visible and functional.

Users WITHOUT permission:

Buttons hidden entirely.

Do not display disabled buttons.

==================================================================
BACKEND SECURITY
================

Do not rely on frontend visibility.

All export endpoints must validate:

CRM_EXPORT

before generating any file.

If permission is missing:

Return:

403 Forbidden

and log the attempt.

==================================================================
VISIBILITY-AWARE EXPORTS
========================

Exports must respect CRM visibility scope.

Example:

Sales Rep

CRM_VISIBILITY_SCOPE = ASSIGNED_ONLY
CRM_EXPORT = TRUE

Export should contain ONLY customers visible to that user.

Never export accounts outside the user's visibility scope.

Examples:

Admin

Visibility = ALL_CUSTOMERS
Export = TRUE

Can export entire CRM.

Sales Manager

Visibility = ALL_CUSTOMERS
Export = TRUE

Can export entire CRM.

Sales Rep

Visibility = ASSIGNED_ONLY
Export = TRUE

Can export only assigned customers.

Sales Rep

Visibility = ASSIGNED_ONLY
Export = FALSE

Cannot export.

==================================================================
EXPORT AUDIT LOGGING
====================

Record all exports.

Log:

* User
* Date
* Time
* Export Type
* Record Count
* Applied Filters

Example:

Rose
Export CSV
312 Records

Group = NC Active
Assigned Rep = Rose

==================================================================
FUTURE PROOFING
===============

CRM_EXPORT permission should automatically apply to future exports including:

* Customer Export
* Reactivation Export
* Notes Export
* Task Export
* Kanban Export
* Customer Intelligence Export

No future export should bypass CRM_EXPORT permission.
