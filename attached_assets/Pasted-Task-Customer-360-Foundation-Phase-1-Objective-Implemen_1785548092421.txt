Task: Customer 360 Foundation (Phase 1)
Objective

Implement the foundational Customer 360 enhancements described in the ERP Architecture Proposal while preserving all existing CRM functionality.

This is an extension of the current CRM, not a redesign.

All changes must be additive and backward compatible.

Guiding Principles
Follow the ERP Architecture Proposal.
Follow the "Extend Rather Than Replace" philosophy.
No existing CRM functionality should be removed.
Existing customer synchronization from BigCommerce must continue working.
Existing notes must remain functional.
Database changes must be additive.
Existing APIs should continue functioning unless intentionally extended.
UI should maintain the current SalesCore look and feel.
Scope

This implementation only covers the Customer 360 foundation.

Do NOT implement:

Product 360
Inventory Intelligence
Warehouse Integration
Fulfillment
Purchase Orders
Vendor 360
Reporting changes

Those will be separate implementations.

Success Criteria
Existing CRM functionality remains fully operational.
Customer accounts can be classified as Customer, Vendor, or Internal.
Active and inactive account management is implemented.
KPIs dynamically reflect current filters.
Notes evolve into Actions without breaking existing data.
To Dos function as CRM actions and are available in a dedicated module.
RBAC controls access to new functionality.
All changes are additive, backward compatible, and aligned with the ERP Architecture Proposal.
The implementation establishes the Customer 360 foundation while leaving future ERP modules (Product 360, Fulfillment, Inventory Intelligence, Notifications, and Vendor 360) free to build on top of it without requiring major refactoring.
