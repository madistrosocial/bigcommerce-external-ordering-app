---
name: Kole feed draft pricing
description: Pricing and stock-safety rules when turning vendor-feed rows into BigCommerce drafts.
---

Keep vendor-feed sync local to the Vendor Catalog. Only an explicit selected-item action may create BigCommerce products, and those drafts stay hidden and disabled; skip an existing SKU rather than overwriting it. Require a valid existing BigCommerce category for each new draft. Until the user supplies a Kole-to-store category mapping, allow a user to choose one category for a batch and override it per product; do not infer mappings. Use `ext_price` as the extended supplier cost when present; it already includes `minimum_qty`. When a feed has no `ext_price`, calculate extended cost as positive `item_piece_price × positive minimum_qty`; never treat the piece price alone as the pack cost. The KCDS default draft markup is selected in vendor settings from 20% through 80% in 5-point steps. Draft creation can temporarily override it, recalculating suggested prices as `roundToCents(extended cost × (1 + markupPercent / 100))`; keep prices and draft titles editable. Blank vendor inventory means unknown, not zero. Live-feed sync remains manual; a user-uploaded CSV is an explicit alternative, never a silent fallback. Use only supplier-provided description text; do not invent product claims when a feed contains only a title.

**Why:** The user clarified that spreadsheet `ext_price` already includes Kole minimum quantity, so multiplying by MOQ again would overstate the draft price. Existing catalog rows may retain unit cost even when the raw feed includes an extended price, so the BigCommerce `cost_price` must be derived from the raw fields too. The user wants KCDS markup as a preset dropdown, not an arbitrary percentage input, and wants an in-dialog override to recalculate suggestions. Some feed rows may contain only a title in their description field; don't assume that is full listing copy. The failed BigCommerce request showed that a category is mandatory; the user will provide the source-to-store mapping later.

**How to apply:** Keep feed sync local to the Vendor Catalog and run it only on a user action. If the live feed is unavailable, report the error; let the user upload a CSV explicitly if they want to proceed. Use `ext_price` or derive extended cost from `item_piece_price × minimum_qty`; use that same extended cost for BigCommerce cost and the markup-based suggestion. Validate the saved default and per-draft override against the 20%-to-80% options in 5-point increments; update all suggested prices when the draft-level choice changes, but keep each price and title editable. Keep the minimum quantity out of stock/order quantity fields. Require a category from the live BigCommerce category list, preserve hidden/disabled visibility and duplicate-SKU protection, and ask for the actual full-description source when the feed contains only a title.
