---
name: Kole feed draft pricing
description: Pricing and stock-safety rules when turning vendor-feed rows into BigCommerce drafts.
---

Keep vendor-feed sync local to the Vendor Catalog. Only an explicit selected-item action may create BigCommerce products, and those drafts stay hidden and disabled; skip an existing SKU rather than overwriting it. Require a valid existing BigCommerce category for each new draft. Until the user supplies a Kole-to-store category mapping, allow a user to choose one category for a batch and override it per product; do not infer mappings. Use `ext_price` as the extended supplier cost when present; it already includes `minimum_qty`. Suggest retail price as `roundToCents(positive ext_price × 1.20)` without multiplying by MOQ again, and keep the price editable. For older feeds without `ext_price`, preserve the `item_piece_price` fallback. Blank vendor inventory means unknown, not zero. Live-feed sync remains manual; a user-uploaded CSV is an explicit alternative, never a silent fallback.

**Why:** The user clarified that spreadsheet `ext_price` already includes Kole minimum quantity, so multiplying by MOQ again would overstate the draft price. The failed BigCommerce request showed that a category is mandatory. The user will provide the source-to-store category mapping later, so category selection must be explicit rather than guessed until then.

**How to apply:** Keep feed sync local to the Vendor Catalog and run it only on a user action. If the live feed is unavailable, report the error; let the user upload a CSV explicitly if they want to proceed. Parse and display `minimum_qty` separately, but calculate selected draft suggestions from `ext_price × 1.20` only. Require a category from the live BigCommerce category list, leave inventory quantities unchanged, and preserve hidden/disabled visibility and duplicate-SKU protection.
